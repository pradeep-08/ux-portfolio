    The product

    What GCC Safe Subway brings together

    Safe Subway is an operational interface for subway barrier management. Its designs include a location list, barrier-status information, selected-location controls, password recovery and a confirmation prompt. Some variants also expose water-level information. The case study centers on the sequence from identifying a location to deliberately requesting a change.

    Problem framing

    The challenge

    An operational control must make both its target and its current state clear. With multiple subway locations in the same application, a user needs to know which location they are viewing before requesting an action. The design challenge is to keep location identity, barrier status and operation controls connected throughout the interaction.

    Users and scope

    Who it serves

    The screens are intended for authorized operational staff rather than members of the public. The visible scope covers monitoring and initiating requests. A design screen does not establish the physical barrier’s response, interlocks or the system’s operational safety performance.

    Task flow

    How the work moves

    Operator

    1. Sign in
    2. Find a subway location
    3. Inspect current status
    4. Open the location control screen
    5. Choose an operation
    6. Review confirmation
    7. Send the request

    A complete implementation should then show a pending state and a device-confirmed result or failure. That final acknowledgement sequence is a recommendation for completion of the experience.

    Design decisions

    Key decisions

    1. The location list supports recognition before action.

    Location names and status information allow operators to select the relevant subway before entering its controls. Search provides a direct route when the operator already knows the target location.

    2. The control screen keeps the selected location visible.

    This creates continuity between the list selection and the action. A confirmation prompt adds a deliberate checkpoint before a manual operation request is submitted.

    3. Screens and task flow are designed together.

    The file includes both UI screens and a task-flow diagram. Together they show how authentication, location selection and operation relate. Draft variants explore additional overview counts and operation history.

    Design outcome and next validation

    What the design achieves, and how to test it

    The design establishes a clear location-to-operation sequence. The next evaluation should check whether operators can identify the intended subway, distinguish current status from an action, cancel an unintended request and recognize a failed or delayed response.

    Pausing to reflect

    Reflection

    For physical controls, clarity depends on more than a prominent button. The user must understand the target, the requested action and whether the device actually completed it.
